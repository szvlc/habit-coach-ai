# Repository Guidelines

HabitCoach AI — Django 6.0 web app (`uv`-managed, Python 3.12+) where users log daily habits and receive AI recommendations grounded in their own history. Canonical context: `@context/foundation/prd.md`, `@context/foundation/tech-stack.md`, `@CLAUDE.md`.

## Hard rules

- **Per-user isolation.** Habits, executions, and recommendations must never reach another user or a logged-out visitor. Every view, queryset, and template filters by `request.user`. Non-negotiable.
- **AI recommendations cite user data.** Each recommendation references concrete elements of the user's history (habit names, weak-day patterns, streaks); generic advice fails the ≥ 75 % criterion (FR-011, FR-013).
- **No backdated logging.** Execution toggling is allowed only for the current day (FR-009).
- **Route Python through `uv`.** `python`, `pip`, and `django-admin` invoked directly bypass `.venv/`.
- **Do not edit between `BEGIN`/`END @przeprogramowani/10x-cli` markers in `@CLAUDE.md`** — that block is regenerated by `10x get`.

## Project structure

- `manage.py`, `habit_coach_ai/` — Django project (settings, URLs, ASGI/WSGI). No apps exist yet; first feature step is `uv run python manage.py startapp <name>` plus wiring it into `INSTALLED_APPS` and `habit_coach_ai/urls.py`.
- `context/foundation/` — PRD, shape-notes, tech-stack. Canonical for product decisions.
- `context/changes/<change>/` — per-change folders; `bootstrap-verification/verification.md` is the scaffold audit trail.
- `.claude/skills/` — 10xDevs toolkit skills bound to this repo.

## Build, test, dev commands

- `uv run python manage.py runserver` — dev server on `http://127.0.0.1:8000/`.
- `uv run python manage.py migrate` / `makemigrations` — apply / generate migrations.
- `uv run python manage.py test` — Django's runner. Single test: append `<app>.tests.<TestClass>.<method>`.
- `uv add <pkg>` — add a runtime dep; updates `@pyproject.toml` and `uv.lock`.
- `uv run --with pip-audit pip-audit` — dependency vulnerability audit.

## Coding style

No linter, formatter, or pre-commit is configured — both are scoped for a later lesson; do not invent commands for tools not in `@pyproject.toml`. The on-disk Django package is `habit_coach_ai` (snake_case); the canonical kebab-case `habit-coach-ai` lives only in `context/foundation/tech-stack.md` metadata — keep them straight.

## Testing

Pytest is **not** configured — do not `import pytest` until `@pyproject.toml` adds it. Tests live under each app's `tests.py` / `tests/`.

## Commits & PRs

Repo is not yet under git. `git init` when ready; until then no convention exists. Capture non-obvious decisions in `context/changes/<change>/change.md` instead of leaning on commit messages.

## Security & configuration

`habit_coach_ai/settings.py` ships `startproject` defaults: `SECRET_KEY` plaintext, `DEBUG = True`, `ALLOWED_HOSTS = []` — move all three behind env vars before any deploy (target: Fly.io). SQLite dev DB will become PostgreSQL in prod; keep `DATABASES['default']` env-driven.
